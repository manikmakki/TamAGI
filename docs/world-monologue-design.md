# Living World — retired design

This was the early design for merging dream and motivation loops into a World Thread. The original document remains in this file’s Git history. Use [navigation and work](navigation-and-work.md), [scheduling](running.md#scheduling-and-model-allowances), and [implementation and evidence](platform-roadmap.md) for the current home platform.

The World Thread remains a scheduled autonomous opportunity. Current platform state comes from persisted actions, pursuits, receipts, and wake conditions. A formatted `[Action]` / `[Outcome]` / `[New State]` monologue is optional; missing narrative cannot erase a completed action. Imaginative descriptions do not prove host operations or create executable tools.

The former Dream Engine activity list, interval/weight configuration, forced monologue progression, and narrative-based recovery directives are retired concepts. Current settings use `autonomy.schedule`, active hours, a post-conversation pause, and explicit rest or event waits. Activity is not required at every opportunity, and tool-call volume does not earn Growth.

Some non-platform code still accepts formatted world responses for compatibility. That adapter is not the canonical storage or execution contract for a home-platform instance.

Relevant decisions are [ADR-0005](adrs/0005-one-execution-lifecycle-and-durable-action-receipts.md), [ADR-0008](adrs/0008-scheduling-offers-opportunities-rest-actually-stops-cognition.md), [ADR-0015](adrs/0015-growth-through-sustained-behavior.md), and [ADR-0016](adrs/0016-room-for-self-directed-work.md). Planned multi-resident behavior is tracked separately in [ADR-0019](adrs/0019-distinct-residents-and-a-shared-world.md).
